# 0018: Installable, offline-capable app (PWA)

Status: Accepted (2026-11-27).

## Context

apex is a static site on GitHub Pages used on phones and laptops, often by a painter at an easel
with a poor connection. Everything it computes runs in the browser, so it can work fully offline.

## Decision

- **Service worker** (`@angular/service-worker`, `ngsw-config.json`), registered only in production
  builds (`provideServiceWorker` in `app.config.ts`; `ng serve` has no worker) once the app is
  stable. It prefetches the app files, including the lazy 3D chunk, so the 3D view works offline.
  Icons and the Google Fonts (CSS and font files) are cached lazily on first use.
- **Web app manifest** (`public/manifest.webmanifest`): name "Artists Palette Explorer", short name
  "apex", standalone display, the neutral mid-gray of the fixed theme (ADR 0004) as background and
  theme color. `start_url` and `scope` are relative (`./`), so they follow the `/apex/` base href.
- **Icons**: the palette logo on the mid-gray background, 192 and 512 px, plus maskable versions with
  a larger safe zone and an `apple-touch-icon` (PNG files in `public/`, rendered from `logo.svg`).
- **Updates**: the default behavior. A new version is downloaded in the background and used from the
  next load; there is no "update available" prompt.

## Consequences

- After a deploy, an already open tab keeps the old version until it is reloaded (twice in the worst
  case: once to fetch, once to switch). Test caching with `npm run build:pages` served under
  `/apex/`, not with `npm start`.
- The initial bundle budget is unchanged; the worker adds about 1 kB to the page and its own files.
- Icons are not generated by the build: if `logo.svg` changes, re-render them.
